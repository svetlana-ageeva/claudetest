# Битрикс: можно оформить заказ на товар с нулевым остатком

Битрикс сам по себе даёт купить товар без остатка, если так разрешено
в настройках. Ниже причины по убыванию вероятности и что с каждой делать.

## 1. Настройки модуля «Торговый каталог» (самая частая причина)

*Настройки → Настройки продукта → Настройки модулей → Торговый каталог*
(`/bitrix/admin/settings.php?mid=catalog`), блок параметров товаров по умолчанию:

| Параметр | Нужное значение |
|---|---|
| Включить количественный учёт | **Да** |
| Разрешить покупку при отсутствии товара (включая отрицательное количество) | **Нет** |
| Резервировать товар при оформлении заказа | **Да** (если нужно резервирование) |

Если количественный учёт выключен, остаток вообще не проверяется.

После сохранения нажмите на той же странице **пересчёт доступности товаров**.
Флаг «Доступен» (`AVAILABLE`) хранится в базе и сам не пересчитывается,
а корзина и фильтр «В наличии» смотрят именно на него.

## 2. Индивидуальные настройки в карточке товара

Карточка товара → вкладка «Торговый каталог» → «Параметры». У каждого товара
и **у каждого торгового предложения (SKU)** есть свои флаги «Количественный
учёт» и «Разрешить покупку при отсутствии». Если там стоит «Да», а не
«по умолчанию», настройка модуля на этот товар не действует.

Такие товары часто появляются после выгрузки из 1С/МойСклад или импорта CSV:
обмен может проставлять `CAN_BUY_ZERO = Y`.

Проверить через SQL:

```sql
SELECT ID, QUANTITY, QUANTITY_TRACE, CAN_BUY_ZERO, AVAILABLE
FROM b_catalog_product
WHERE CAN_BUY_ZERO <> 'D' OR QUANTITY_TRACE <> 'D';
```

Массово сбросить на «по умолчанию»: скрипт `bitrix/tools/reset_can_buy_zero.php`.
Сначала запустите с `$dryRun = true`. Если после следующего обмена флаги
вернулись, отключите их передачу в настройках обмена с 1С.

## 3. Складской учёт

Если включён складской учёт, общий остаток (`QUANTITY`) меняется только
документами (приход, списание, перемещение). Если в карточке стоит остаток 0,
а по складам числится товар, или наоборот, проверьте документы и
остатки по складам.

## 4. Товар лежал в корзине до того, как закончился

Корзина проверяет остаток в момент добавления и при обновлении. Если
шаблон `sale.order.ajax` или корзины доработан так, что позиции не
обновляются (кеш, кастомный AJAX), в заказ может попасть позиция, которая
уже закончилась.

## 5. Своя кнопка «Купить» / «Купить в 1 клик»

Если товар добавляется в корзину своим кодом через `Basket::createItem()`
без `PRODUCT_PROVIDER_CLASS` (или через старый `CSaleBasket::Add` без
`PRODUCT_PROVIDER_CLASS`), Битрикс не знает, что это товар каталога,
и остаток не проверяет. Найти такие места:

```bash
grep -rn "createItem\|CSaleBasket::Add\|Add2Basket" local/ bitrix/templates/
```

Правильно добавлять через `\Bitrix\Catalog\Product\Basket::addProduct()`:
он учитывает остатки.

## Страховка: запрет на уровне сохранения заказа

`bitrix/local/php_interface/include/order_stock_guard.php` — обработчик
`OnSaleOrderBeforeSaved`. Он не даёт сохранить **новый** заказ, если
остатка меньше, чем заказано, из какого бы места ни пришёл заказ.
Подключается одной строкой в `/local/php_interface/init.php`:

```php
require_once __DIR__ . '/include/order_stock_guard.php';
```

`ORDER_STOCK_GUARD_STRICT = true` блокирует всё без остатка, даже товары
с «Разрешить покупку при отсутствии». Если часть ассортимента законно
продаётся **под заказ** (например, ворота под размер), поставьте `false`:
тогда проверка учитывает флаги товара, и таким товарам достаточно
оставить `CAN_BUY_ZERO = Y`.

## Порядок действий

1. Пункт 1: настройки модуля и пересчёт доступности.
2. SQL из пункта 2. Если есть строки, сбросьте их скриптом.
3. Проверьте заказ на товар с остатком 0 из карточки, из корзины и через «Купить в 1 клик».
4. Если какой-то путь всё равно пропускает заказ, ищите свой код (пункт 5) и подключите страховку.
